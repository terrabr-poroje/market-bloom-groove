## وضعیت استقرار فعلی
در اجرای GitHub Actions شماره 11 (commit `ee39d3e4314aa70ba270b937e4d8aa2a26151f96`) مراحل build، deploy به Worker موجود `terrabar-market` و بررسی HTTP موفق بودند. زمان‌های ثبت‌شده برای مسیرهای /، /auth، /announce و /requests روی دامنه‌های اصلی و www حدود 0.11 تا 0.57 ثانیه بوده است. این آزمون فقط پاسخ HTTP و وجود متن ترابار را تأیید می‌کند؛ تعاملات مرورگر، فرم‌ها و عملیات واقعی Supabase را تأیید نمی‌کند.

## اختلاف‌های مهم قبل از ادغام
1. نسخه زنده Supabase دارای 42 migration ثبت‌شده است؛ baseline مورخ ۱۸ اکتبر قبل از تغییرات بعدی قرار دارد. بنابراین اجرای `db push` یا اعمال مجدد migrationهای این شاخه روی تولید ممنوع است تا اختلاف نسخه‌ها و checksum/محتوای فایل‌ها تطبیق داده شود.
2. شاخه `main` پس از baseline تغییرات قابل‌توجهی در پوسته بازار، صفحه اصلی، ویترین و مسیرهای درخواست دارد. مقایسه نشان می‌دهد تاریخچه‌ها واگرا هستند؛ ادغام کامل یا بازگرداندن کورکورانه main امن نیست.
3. بازرسی فقط‌خواندنی صفحات زنده، عنوان و محتوای فارسی را نشان داد. مسیرهای اعلام بار و درخواست خرید بدون ورود، صفحه ورود را پیشنهاد می‌کنند که با محدودیت دسترسی مورد انتظار سازگار است. استخراج محتوای متنی به‌تنهایی حضور یا عملکرد کنترل‌های تعاملی را ثابت نمی‌کند.
4. هشدارهای امنیتی/عملکردی Supabase شامل شش جدول دارای RLS بدون policy (از جمله جداول پیام‌رسانی/وب‌هوک)، یک تابع `SECURITY DEFINER` قابل اجرا توسط `authenticated` و نه مورد سیاست permissive تکراری است. این موارد باید با بررسی مصرف‌کننده‌ها و تست نقش‌ها اصلاح شوند؛ حذف یا تغییر دسترسی در این مرحله انجام نمی‌شود.

## گام‌های الزامی برای تکمیل
- گرفتن پشتیبان واقعی از داده و schema دیتابیس؛ شاخه GitHub به‌تنهایی پشتیبان دیتابیس نیست.
- مقایسه 42 migration زنده با فایل‌های SQL موجود در مخزن و تولید فهرست اختلاف‌ها.
- اجرای build و تست‌های واحد/نوع در شاخه بازسازی.
- آزمون مرورگری واقعی برای ثبت‌نام، OTP، ورود مدیر، نقش‌ها، اعلام بار، جست‌وجو، درخواست سفارش، ویترین و مدیریت.
- پس از تأیید نتیجه و نسخه، ادغام کنترل‌شده و استقرار؛ تا آن زمان تولید بدون تغییر می‌ماند.
