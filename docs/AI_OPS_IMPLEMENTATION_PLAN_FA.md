## معماری پیشنهادی، هنوز اجرا نشده
1. **رابط دستور فارسی:** در مرحله اول از همین ChatGPT و اتصال‌های مجاز GitHub/Supabase/Cloudflare/Render استفاده شود تا بدون خرید سرویس جدید، گردش کار و محدودیت‌ها سنجیده شود.
2. **عامل پایدار در صورت نیاز واقعی:** پس از اثبات نیاز، یک سرویس کوچک مستقل و محدود برای دریافت فرمان، صف کار، ثبت رویداد و اجرای ابزارهای allowlist بررسی شود. انتخاب بین Cloudflare Workers و گزینه‌های دیگر فقط پس از مقایسه هزینه، دسترسی از ایران، امنیت و پایداری انجام شود.
3. **مدل هوش مصنوعی:** استفاده از API فقط پس از برآورد مصرف و تأیید هزینه. اشتراک ChatGPT به‌تنهایی به معنی اعتبار API نیست.
4. **ابزارهای محدود:** فقط عملیات مشخص GitHub، خواندن Supabase، اجرای تست و مشاهده وضعیت سرویس‌ها. دسترسی به secrets، داده‌های شخصی کاربران و عملیات نوشتن production به‌صورت پیش‌فرض مسدود باشد.
5. **گردش تغییر کد:** تحلیل → تغییر در شاخه اختصاصی → build/lint/test → گزارش diff → PR برای بازبینی. هیچ merge یا deploy خودکاری از طرف عامل انجام نشود.
6. **عملیات دیتابیس:** فقط بررسی read-only در حالت پیش‌فرض. هر migration باید جداگانه شرح داده، روی محیط آزمایشی تست و با تأیید صریح اجرا شود. هرگز snapshot اسکیمای تولید را به‌عنوان migration دوباره اجرا نکن.
7. **انتشار:** به دلیل workflowهای متصل به main، ادغام PR و انتشار Cloudflare/Render دو مرحله حساس و نیازمند تأیید صریح مستقل هستند.
8. **پایش:** بررسی دوره‌ای دسترس‌پذیری، buildها و خطاهای workflow؛ گزارش هشدار بدون تغییر خودکار زیرساخت.

## سطوح مجوز
- **سطح A – فقط خواندن:** بررسی کد، وضعیت workflow، لاگ‌های مجاز، اسکیمای امن و health check عمومی.
- **سطح B – تغییر آزمایشی:** ایجاد/ویرایش فایل و commit فقط در شاخه آزمایشی، اجرای تست و ساخت PR؛ بدون merge.
- **سطح C – تغییر production:** تغییر داده، schema، RLS، secrets، DNS، دامنه، Worker/Render settings، پرداخت/پیامک و merge/deploy. فقط پس از توضیح دقیق اثر و تأیید روشن همان اقدام.
- **خرید/هزینه:** هر اشتراک، API credit، ارتقای پلن یا سرویس جدید نیازمند اعلام قیمت و تأیید جداگانه است.
